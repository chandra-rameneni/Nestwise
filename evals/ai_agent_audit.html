Audit findings, most important first

Problem The AI reviewer has never been checked against human labels

No one has measured how often the reviewer catches a real failure or wrongly flags a good reply. On this run it caught none of the 3 clear failures, so its 27 of 28 overstates quality.

Fix: you label about 50 good and 50 bad replies, then measure what share of bad replies the reviewer catches and what share of good ones it passes (the validate-evaluator skill).

Problem The reviewer can't see the facts it is judging

It sees each reply and a one-line list of steps, but not what the tools returned or the store policy text. It had no way to know 72 business days was wrong. It also checks five things at once (misunderstanding, wrong facts, claiming an order, ignoring the question, confusion), which makes its verdicts vague.

Fix: give the reviewer the tool results and policy text, and split it into one check per failure type, starting with wrong fact compared with the tool data (the write-judge-prompt skill).

Problem Some failures that code could catch have no code check

The leaked [What I did …] note, numbers that differ from the store policy, and tap Pay before Approve can all be checked with simple code, every run, for free. One existing check is too strict and failed a correct reply over include versus included.

Fix: add those three code checks and loosen the delivery pattern (the write-code-eval skill).

Problem The newest AI failures aren't written up or tested

The failure log is grounded in real shopper problems, which is good, but its last entries (21 Nov) are about the old rules engine. Problems you found on 22 and 23 Nov, like not asking on a broad request and inventing a reason for its picks, aren't in the log or in the 28 conversations.

Fix: log them, add a conversation for each, and do a fresh review pass of AI-mode chats (the error-discovery skill).

Problem Too few, too similar conversations

There are 64 replies across 28 conversations, and 14 of the 28 start with the same sofa search. That's well short of the roughly 100 varied chats where new failure types stop showing up.

Fix: generate varied shopper chats across product types, budgets and moods, then review them (the generate-synthetic-data skill).

OK What's already right

  • Every check is a clear pass or fail, with no 1 to 5 scores.
  • Code, not the AI, checks the cart, invented prices and payment refusals.
  • Tests are re-run after changes. This run used today's prompt.
  • The reviewer is a different model from the one that answers.
  • You test in the real store, and the Inspector shows every step of a chat.
